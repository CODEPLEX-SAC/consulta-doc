# 📦 PROMPT — Microservicio Consulta RUC/DNI con Padrones SUNAT + CockroachDB

## 🎯 Objetivo del proyecto

Construir un microservicio Node.js / PHP / Python que:

1. **Descargue automáticamente** los dos Padrones Reducidos oficiales de SUNAT.
2. **Importe** la data a CockroachDB para consulta local rápida.
3. **Combine** datos del Padrón con el scraper de la consulta RUC pública que ya está implementado en el proyecto.
4. **Exponga** un endpoint HTTP que devuelva el JSON estándar:

```json
{
  "success": true,
  "data": {
    "rucdni": "10448539500",
    "nombrerazon": "NUÑEZ VASQUEZ GLADYS NATALI",
    "activo": 1,
    "estadosunat": 1,
    "direccion": "CAL. HUASCAR NRO. 180      JOSE LEONARDO ORTIZ",
    "ubigeo": "140105",
    "estado": "ACTIVO",
    "condicion": "HABIDO"
  }
}
```

### Drivers recomendados
- **Node.js**: `pg` (node-postgres) — CockroachDB es 100% wire-compatible con PostgreSQL.
- **PHP**: `pdo_pgsql`.
- **Python**: `psycopg2-binary` o `psycopg[binary]` v3.

### Notas de CockroachDB vs PostgreSQL
- Soporta SQL estándar PostgreSQL.
- Para `UPSERT` masivo usar `INSERT ... ON CONFLICT (ruc) DO UPDATE SET ...` o el `UPSERT` nativo de Cockroach.
- **Evitar transacciones largas** (>5 min). Para importar millones de filas: usar batches de 1000-5000 filas, cada uno en transacción independiente.
- **Usar `PRIMARY KEY` con UUID o el RUC mismo**: Cockroach distribuye por hash del PK.

## 🔧 Componentes a implementar

### Componente 1 — `PadronDownloader`

**Responsabilidad**: descargar los dos ZIPs desde SUNAT, descomprimirlos, dejar los TXT listos para procesar.

**Pseudocódigo:**
```
function descargarPadron(tipo: "ruc" | "local_anexo"):
  url = tipo == "ruc"
    ? "http://www2.sunat.gob.pe/padron_reducido_ruc.zip"
    : "http://www2.sunat.gob.pe/padron_reducido_local_anexo.zip"

  # 1. Marcar inicio en padron_meta
  upsert padron_meta: estado_ultimo_import = "in_progress"

  # 2. Descargar ZIP a /tmp con stream (NO cargar en memoria, son cientos de MB)
  descargar(url) → /tmp/padron_{tipo}.zip

  # 3. Calcular SHA256 del ZIP
  hash = sha256(/tmp/padron_{tipo}.zip)

  # 4. Comparar con hash anterior; si igual, SKIP el import
  if hash == padron_meta.hash_archivo:
    log "Padrón {tipo} sin cambios desde la última descarga"
    return { skipped: true }

  # 5. Descomprimir
  unzip /tmp/padron_{tipo}.zip → /tmp/padron_{tipo}.txt

  return { ruta: "/tmp/padron_{tipo}.txt", hash: hash }
```

**Detalles técnicos:**
- Usar **streaming HTTP** (no cargar el ZIP entero a memoria). En Node: `axios` con `responseType: 'stream'`. En Python: `requests` con `stream=True`. En PHP: `fopen` con `fwrite`.
- Timeout: 30 minutos para la descarga.
- User-Agent realista (Chrome/Firefox).
- Validar que el archivo descargado no esté vacío (size > 10 MB).
- Si la descarga falla 3 veces, escalar al log de errores y abortar (no eliminar la tabla anterior).

### Componente 2 — `PadronImporter`

**Responsabilidad**: leer el TXT línea por línea, parsear, hacer UPSERT en batches a CockroachDB.

**Estructura del archivo Padrón Reducido RUC:**
- Codificación: **ISO-8859-1** (latin1) — NO UTF-8.
- Separador: **pipe `|`**.
- Sin header (la primera línea ya es data).
- Una línea por RUC.

**Columnas esperadas (validar al descargar el archivo real):**
```
0:  RUC
1:  NOMBRE_O_RAZON_SOCIAL
2:  ESTADO_CONTRIBUYENTE
3:  CONDICION_DOMICILIO
4:  UBIGEO
5:  TIPO_VIA
6:  NOMBRE_VIA
7:  CODIGO_ZONA
8:  TIPO_ZONA
9:  NUMERO
10: INTERIOR
11: LOTE
12: DEPARTAMENTO (DPTO. de la dirección)
13: MANZANA
14: KILOMETRO
15: FECHA_INSCRIPCION  (formato YYYYMMDD)
```

> **IMPORTANTE**: SUNAT puede modificar el orden o agregar columnas. Al implementar, descargar UN archivo manualmente, abrirlo con `head -5 archivo.txt` y validar el orden real antes de codificar el parser.

**Pseudocódigo del importer:**
```
function importarPadronRuc(rutaArchivo, hashArchivo):
  client = conectarCockroachDB(SSL=require)

  batch = []
  totalProcesados = 0
  BATCH_SIZE = 2000

  abrir archivo en streaming (encoding=latin1)

  for cada linea in archivo:
    if linea está vacía: continue

    campos = linea.split("|")
    if campos.length < 16: log warning; continue

    row = {
      ruc: campos[0].trim(),
      nombre_razon: campos[1].trim(),
      estado_contribuyente: campos[2].trim(),
      condicion_domicilio: campos[3].trim(),
      ubigeo: campos[4].trim(),
      tipo_via: campos[5].trim(),
      nombre_via: campos[6].trim(),
      codigo_zona: campos[7].trim(),
      tipo_zona: campos[8].trim(),
      numero: campos[9].trim(),
      interior: campos[10].trim(),
      lote: campos[11].trim(),
      departamento_addr: campos[12].trim(),
      manzana: campos[13].trim(),
      kilometro: campos[14].trim(),
      fecha_inscripcion: parseFecha(campos[15]),  # YYYYMMDD → YYYY-MM-DD
    }

    # Construir dirección completa lista para devolver
    row.direccion_completa = armarDireccion(row)

    batch.push(row)

    if batch.length >= BATCH_SIZE:
      ejecutarUpsertBatch(client, batch)
      totalProcesados += batch.length
      batch = []
      log "Procesadas: {totalProcesados}"

  # Procesar último batch parcial
  if batch.length > 0:
    ejecutarUpsertBatch(client, batch)
    totalProcesados += batch.length

  # Marcar metadata
  upsert padron_meta:
    padron_tipo = "ruc"
    ultima_importacion = now()
    filas_importadas = totalProcesados
    estado_ultimo_import = "ok"
    hash_archivo = hashArchivo

  log "Import completo: {totalProcesados} filas"
```

**Función `armarDireccion`:**
```javascript
function armarDireccion(row) {
  const partes = [];

  if (row.tipo_via && row.nombre_via) {
    partes.push(`${row.tipo_via} ${row.nombre_via}`);
  }
  if (row.numero && row.numero !== '-' && row.numero !== '') {
    partes.push(`NRO. ${row.numero}`);
  }
  if (row.interior && row.interior !== '-' && row.interior !== '') {
    partes.push(`INT. ${row.interior}`);
  }
  if (row.manzana && row.manzana !== '-' && row.manzana !== '') {
    partes.push(`MZA. ${row.manzana}`);
  }
  if (row.lote && row.lote !== '-' && row.lote !== '') {
    partes.push(`LT. ${row.lote}`);
  }
  if (row.kilometro && row.kilometro !== '-' && row.kilometro !== '') {
    partes.push(`KM. ${row.kilometro}`);
  }

  let direccion = partes.join(' ');

  // Sufijo zona/distrito al estilo SUNAT (formato compatible miapicloud)
  if (row.tipo_zona && row.codigo_zona) {
    direccion += `      ${row.tipo_zona} ${row.codigo_zona}`;
  }

  return direccion.trim();
}
```

### Componente 4 — `ConsultaService`

**Responsabilidad**: orquestar la respuesta combinando Padrón + scraper público.

**Lógica:**

```javascript
async function consultar(rucdni) {
  // 1. Validar formato
  const ruc = normalizarInput(rucdni);
  if (!validarFormato(ruc)) {
    return { success: false, error: "Formato inválido", code: 422 };
  }

  // 2. Caché de respuestas finales
  const cached = await getCacheConsulta(ruc);
  if (cached) return cached;

  // 3. Lookup en Padrón (instantáneo, BD local)
  const padron = await db.query(
    `SELECT * FROM padron_reducido_ruc WHERE ruc = $1`, [ruc]
  );

  // 4. Scraping público en paralelo (datos en vivo)
  // Solo si el Padrón tiene match (para no gastar captcha en RUC inexistentes)
  let publica = null;
  if (padron.length > 0) {
    try {
      publica = await scraperConsultaPublica(ruc); // YA EXISTE en el proyecto
    } catch (e) {
      log.warn(`Scraping público falló para ${ruc}: ${e.message}`);
    }
  } else {
    // Si no está en Padrón, intentar scraping (puede ser RUC nuevo no en padrón aún)
    try {
      publica = await scraperConsultaPublica(ruc);
    } catch (e) {
      return { success: false, error: "RUC no encontrado", code: 404 };
    }
  }

  // 5. Merge: prioridad pública para datos en vivo, Padrón para dirección/ubigeo
  const data = mergeData(padron[0], publica);

  if (!data.nombrerazon) {
    return { success: false, error: "RUC no encontrado", code: 404 };
  }

  // 6. Cachear 24h
  await setCacheConsulta(ruc, data, 24 * 3600);

  return { success: true, data };
}
```

**Función `mergeData`:**

```javascript
function mergeData(padronRow, publicaRow) {
  // Si solo hay una fuente, usarla
  const usarSolo = !padronRow ? publicaRow : (!publicaRow ? padronRow : null);

  return {
    rucdni: padronRow?.ruc || publicaRow?.ruc,
    nombrerazon: publicaRow?.nombrerazon || padronRow?.nombre_razon,
    activo: esActivo(publicaRow?.estado || padronRow?.estado_contribuyente) ? 1 : 0,
    estadosunat: 1,
    direccion: dirEsValida(publicaRow?.direccion)
               ? publicaRow.direccion
               : padronRow?.direccion_completa,
    ubigeo: padronRow?.ubigeo || null,  // SIEMPRE del Padrón (la pública no lo trae)
    estado: publicaRow?.estado || padronRow?.estado_contribuyente,
    condicion: publicaRow?.condicion || padronRow?.condicion_domicilio
  };
}

function esActivo(estado) {
  return estado === 'ACTIVO';
}

function dirEsValida(direccion) {
  return direccion && direccion.trim() !== '' && direccion.trim() !== '-';
}
```

### Componente 6 — Scheduler

**Refresh diario** de ambos padrones:

```
# Cron expression: diariamente 6:30am hora Lima (11:30 UTC)
30 11 * * *  /usr/bin/node /app/jobs/refresh-padrones.js
```

Implementación:
```javascript
async function jobRefreshPadrones() {
  log.info("Iniciando refresh de padrones");

  for (const tipo of ['ruc', 'local_anexo']) {
    try {
      const result = await descargarPadron(tipo);
      if (result.skipped) {
        log.info(`Padrón ${tipo} sin cambios, skip import`);
        continue;
      }

      if (tipo === 'ruc') {
        await importarPadronRuc(result.ruta, result.hash);
      } else {
        await importarPadronLocalAnexo(result.ruta, result.hash);
      }
    } catch (e) {
      log.error(`Error procesando padrón ${tipo}: ${e.message}`);
      // NO abortar: si uno falla, intentar el siguiente
      await marcarPadronError(tipo, e.message);
      // Enviar alerta (Slack, email, etc.)
    }
  }

  log.info("Refresh de padrones completado");
}
```

## 🛡️ Manejo de errores y casos límite

| Caso | Detección | Acción |
|---|---|---|
| ZIP de SUNAT corrupto | unzip falla o tamaño < 10MB | Reintentar 3 veces con backoff (5min, 15min, 60min). Mantener data anterior |
| RUC en Padrón pero baja en pública | Estados distintos | Priorizar pública (más fresca) |
| RUC en pública pero NO en Padrón | RUC nuevo (creado hoy) | Devolver con `ubigeo: null`, marcar warning |
| RUC en Padrón pero NO en pública | RUC dado de baja sin actualizar Padrón | Devolver con datos del Padrón |
| Captcha falla 3 veces | Scraping abortado | Devolver solo data del Padrón con warning |
| BD caída | Connection error | Retry 3 veces. Si persiste, solo scraping |
| Padrón > 7 días sin actualizar | Check en `padron_meta` | Alerta en `/health`, log warning, pero seguir respondiendo |
| Encoding mal interpretado | Caracteres `Ã±` `Ã©` en data | El importer DEBE usar latin1 explícito |

## ✅ Criterios de aceptación

El sistema está listo para producción cuando:

1. ✅ `GET /consultaDocumento/10448539500` devuelve **exactamente** el JSON esperado con `ubigeo: "140105"`.
2. ✅ `GET /consultaDocumento/20563083183` devuelve `ubigeo: "150132"`.
3. ✅ `GET /consultaDocumento/99999999999` devuelve `success: false, code: 404`.
4. ✅ `GET /consultaDocumento/44853950` (solo DNI) auto-convierte a RUC y responde.
5. ✅ Una segunda consulta del mismo RUC devuelve en < 50ms (caché hit).
6. ✅ El cron job corre diariamente y actualiza `padron_meta`.
7. ✅ `/health` reporta `status: ok` con padrones < 24h de antigüedad.
8. ✅ El sistema sigue respondiendo aunque el scraper público falle (con data del Padrón).
9. ✅ El sistema sigue respondiendo aunque el Padrón esté desactualizado (con data scraping + warning).
10. ✅ NO hay credenciales hardcoded en el código (todo en `.env`).

## 🔒 Seguridad — Recordatorios obligatorios

1. **Rotar la contraseña de `dev_user`** antes de subir a producción.
2. **`.env` en `.gitignore`** desde el día 1.
3. **Restringir IP** del CockroachDB en lo posible (firewall, VPN, security groups).
4. **Endpoints admin protegidos** con API key o JWT.
5. **Rate limit** en el endpoint público (ej: 100 req/min por IP).
6. **No logear el RUC completo en producción** si tu sistema procesa datos de personas naturales (privacidad).
7. **Cumplimiento Ley 29733**: si almacenas datos de personas naturales (RUC tipo 10), tu sistema debe tener finalidad legítima documentada.
